# 开源复用评估

日期：2026-10-08 · 状态：仓库文档调研；Dotting 2.1.18 已完成隔离验证，PNG/ZIP 基础库已集成验证，其他编辑器候选未实测

## 1. 结论

无需把整个编辑器从零开发。推荐复用基础库，优先验证像素专用组件；产品自行控制 RGBA 数据、帧管理、动画时钟和项目级历史。Dotting 基础交互验证通过，但不建议直接用于当前完整范围，详见 [Dotting 验证报告](05-dotting-validation.md)。

## 2. 候选方案

| 候选 | 官方说明及许可 | 本项目判断 |
| --- | --- | --- |
| [Dotting](https://github.com/hunkim98/dotting) | React 像素编辑组件；提供画笔、擦除、网格、平移缩放和数据 hooks；MIT | 最值得先验证的嵌入式候选；像素使用带颜色字符串的对象结构，与 RGBA 数组需要适配 |
| [Piskel](https://github.com/piskelapp/piskel) | 完整网页精灵与像素动画编辑器；JavaScript/HTML/CSS；Apache-2.0 | 可参考帧管理和动画交互；直接 fork 是另一条完整产品路线，不等同于安装 React 组件 |
| [react-pixel-art-canvas](https://github.com/geoffmiller/react-pixel-art-canvas) | React Canvas 像素绘制组件 | 次级候选；需要补充核查许可、React 兼容性及完整帧能力，不直接定为生产依赖 |
| [react-konva](https://github.com/konvajs/react-konva) | React 的 Konva 2D Canvas 组件 | 面向图形对象编辑；当前逐像素修改优先直接使用图像缓冲，不为每个像素创建一个对象 |
| [fast-png](https://github.com/image-js/fast-png) | JavaScript PNG 编码与解码库 | 优先验证编解码、格式展开及透明像素保真；库输出需要规范化为本项目 RGBA 格式 |
| [fflate](https://github.com/101arrowz/fflate) | 压缩与 ZIP 库，提供异步及流式接口 | 优先验证批量 PNG 打包；在产品 Worker 中组织任务、进度和资源释放 |

上述功能依据仓库说明；其他候选未进行源代码完整审计、性能测试或当前版本兼容性验证；Dotting 的已测项目与限制见专项报告。仓库存在和功能匹配不等于已通过生产选型。

## 3. 三条实现路线

1. **嵌入 Dotting**：可减少画布交互开发，但需要确认外部数据与内部历史能否协调，且对象数据模型不会造成上限项目内存过大。
2. **自研精简 Canvas 核心 + 基础库**：需要开发坐标、笔画和历史，但能直接控制保真与多帧流程；已采用并完成首期实现。
3. **fork Piskel**：适合主要目标是快速获得完整像素创作工具的情况；需要维护整套应用，并额外处理 Next.js 产品整合和本项目保真要求。当前不选择此路线。

## 4. Dotting 采用门槛

- 能从外部数据恢复精确尺寸和颜色；导入显示、帧切换及编辑事件不丢失 alpha 或透明像素下 RGB。
- 获取每次笔画的坐标与颜色差分，且可以让产品级历史成为唯一历史来源，避免两套撤销系统冲突。
- 产品 RGBA 数据为事实来源；如组件无法表示完全透明下的 RGB，可保留源数组，只将明确发生编辑的像素差分写回。必须证明无编辑显示或帧切换不会覆盖源数据。
- 外部状态更新不触发递归事件、重复笔画或错误历史；连续拖动形成一个事务。
- 满足 1024×1024 单帧与预算内多帧的性能和内存门槛。
- Next.js 客户端加载、开发时重复挂载与资源清理正常；当前 React 版本兼容。

任何关键门槛无法满足或适配比精简核心复杂时，采用自研 Canvas 2D。动画与帧顺序由本项目实现，不把图层功能视为动画帧功能。

## 5. 基础库采用门槛

PNG：验证灰度、RGB、RGBA、索引色和透明信息展开，拒绝不支持的 16 位与 APNG，保证无编辑往返 RGBA 一致。优先无损 RGBA 输出，不启用量化。

ZIP：验证文件命名、排序编号、解压正确性、峰值内存以及失败后的重试。PNG 已压缩，打包压缩级别按耗时和收益实测决定。

正式采用前检查具体版本的 LICENSE、依赖许可、发行包、维护记录、兼容性与已知问题；保留相应许可和通知文件。版本在验证后锁定，不依据星数或未核实的活跃度作选择。

## 7. 最终复用结果

编辑核心采用自研 Canvas 2D；PNG 编解码复用 fast-png 6.4.0，压缩及 ZIP 复用 fflate 0.8.3，图标采用 lucide-react。PNG 兼容补充由项目负责；透明像素保真、低位深与 Adam7、异常输入均已测试。准确依赖版本见 package-lock.json，许可见 THIRD_PARTY_NOTICES.md。
